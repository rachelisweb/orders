# חיבור iCount מאובטח

המפתח של iCount נשמר כסוד של Supabase Edge Functions בלבד. אין להדביק אותו ב-`config.js`, ב-JavaScript של האתר או ב-GitHub.

## לפני הפעלה

1. ב-iCount צור API Token עבור משתמש שמורשה ליצור ולקרוא חשבוניות.
2. אין צורך לאפשר ל-iCount לשלוח מיילים. הפונקציה שולחת `send_email: false`; מערכת ההזמנות מצרפת את ה-PDF למייל המשלוח.
3. ודא שמחירי הדגמים במערכת הם לפני מע״מ ושבכרטיסי הלקוחות מופיעים שם עסק, ח.פ/ע.מ וכתובת נכונים.

## שמירת המפתח

מתוך תיקיית הפרויקט `frontend`:

```powershell
supabase secrets set ICOUNT_API_TOKEN="הדבק-כאן-את-הטוקן"
```

הפקודה שולחת את הסוד ישירות ל-Supabase. היא אינה כותבת אותו לקובץ מקומי.

## סדר הפעלה לאחר אישור

```powershell
supabase db push
supabase functions deploy icount-invoice
```

לאחר מכן פותחים הזמנה במצב „מוכנה לאיסוף”, בוחרים „הפקת חשבונית”, בודקים את התצוגה המקדימה ומאשרים.

## מנגנוני הגנה

- חשבונית מס (`invoice`) וחשבונית מס־קבלה (`invrec`) מעל 5,000 ₪ **לאחר הנחה ולפני מע״מ** נחסמות בלי ח.פ/ע.מ או תעודת זהות של העוסק בת 9 ספרות. החסימה חלה גם על חשבונית גמישה ועל בקשת API ישירה. קבלה רגילה וחשבונית זיכוי אינן כלולות בחסימה.
- לקבלת מספר הקצאה בפועל נדרשת גם הרשאה פעילה ל„חשבוניות ישראל” בחשבון iCount. נוכחות מזהה לקוח מאפשרת בקשת הקצאה, ואינה מבטיחה שרשות המסים אישרה אותה. ראו [ההסבר הרשמי של iCount](https://www.icount.co.il/blog/invoice-israel/) ו[רשות המסים](https://www.gov.il/he/service/request-assignment-number-for-tax-invoice).

- הפקה מותרת למנהל בלבד ורק להזמנה במצב „מוכנה לאיסוף”.
- השרת קורא מחדש את הלקוח, הפריטים והמחירים; הוא אינו סומך על סכומים מהדפדפן.
- המע״מ קבוע ל-18% ותאריך התשלום נקבע לסוף חודש ההפקה.
- `sanity_string` ייחודי, נעילת מסד ואינדקס ייחודי מונעים חשבונית כפולה.
- אם iCount יצר מסמך אך שמירתו במערכת לא הושלמה, הניסיון הבא ממשיך מאותו מספר מסמך במקום ליצור חדש.
- חשבונית iCount אינה ניתנת למחיקה מהמערכת. טעות חשבונאית מטופלת בביטול או בזיכוי מתועד.
